# 会议侧边栏与 Todo 交互建议

## 产品形态

桌面端或移动端以轻量侧边栏存在，不抢占会议注意力。默认只显示当前阶段和一个最高价值提示；用户展开后再看完整进度、需求缺口和后续选择。

## 三个时刻

### 会前

- 显示本次会议目标、已知参与方和待确认材料。
- 根据历史 PRD/客户确认表给出 3 个以内的关键问题。

### 会中

- 显示 ASR/说话人质量状态，但不滚动展示完整 transcript。
- 当出现影响范围或验收的关键缺口时，提示“建议追问”，用户可忽略、收藏或标记已问。
- 不在每段对话后弹提示；相同主题合并，优先级由产品影响决定。

### 会后

- 显示 ASR、会议纪要、Product Discovery 和 QA 进度。
- 生成可交互 Todo：审阅客户问题、确认潜在需求、生成 PRD、生成技术架构、生成客户需求确认表、仅保存纪要。
- 用户可以拖动排序、删除 Agent 建议、添加自己的下一步；这些修改回写 Execution Ledger，而不是创建第二套任务列表。

## 推荐信息层级

```text
[会议已结束] 纪要与需求分析完成

当前建议
┌ 先确认客户的实际验收方式
│ 不确认会影响 PRD 和开发验收
└ [标记已问] [稍后] [查看证据]

下一步
☐ 审阅客户问题（4）
☐ 生成带待确认项的 PRD
☐ 生成客户需求确认表
+ 添加自己的步骤
```

## 前端不应做的事情

- 不自己维护 Todo 真相源。
- 不根据 UI 勾选直接把任务标记为已验收。
- 不把所有 Agent 推断都实时打断会议。
- 不用完整 transcript 填满主界面。
- 不把“生成 PRD”默认当作每次会议的强制下一步。
