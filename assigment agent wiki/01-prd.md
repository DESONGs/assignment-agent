# 日常会议终结与文档撰写 Agent PRD

## 1. 产品定位

这是一个本地优先、飞书协同、Rokid 文件接入的会议终结 Agent。它面向高频会议、客户沟通、技术方案讨论和运营复盘，把录音/视频/图片/飞书上下文转化为可追溯的会议纪要和后续文档。

核心能力不是简单摘要，而是把会议内容变成下一步可执行资产：

- 会议纪要：记录事实、结论、分歧、行动项和风险。
- PRD：把产品需求会转成目标、用户、范围、功能、验收标准。
- 技术架构文档：把技术讨论转成系统边界、模块、接口、数据流、风险和测试。
- 运营文档：把运营讨论转成策略、流程、SOP、指标和复盘机制。
- 客户需求确认表：把模糊需求转成待确认问题和下一次沟通清单。

## 2. 背景与参考

PDF 参考会议纪要展示了一个典型工作模式：从业务会议中提取项目定位、MVP 边界、数据安全、商业模式、超级个体协作和后续行动项。本 Agent 要把这种整理能力产品化，并能持续沉淀成模板、skill 和知识库。

参考会议中的关键原则会进入产品设计：

- 先做可控 MVP，不一开始追求复杂平台。
- 数据安全和部署边界必须前置确认。
- 输出物要服务下一次沟通和交付，而不是只生成漂亮摘要。
- 业务表达应面向“AI 企业服务、工作流咨询、部署培训、持续优化”，避免落入一次性外包。
- 通过 agent、知识库和极小团队支持超级个体交付。

## 3. 目标用户

- 高频开会的个人工作者：需要会后快速整理纪要和任务。
- AI 企业服务/FDE/超级个体：需要把客户会议转成 PRD、架构和需求确认表。
- 创业团队负责人：需要把会议内容沉淀到飞书知识库并推动行动项。
- 需要使用 Rokid 智能眼镜记录会议素材的人：希望将导出的音视频文件快速进入总结流程。

## 4. 用户问题

- 会议结束后信息分散在录音、视频、聊天记录、口头结论和个人记忆中。
- 单纯摘要不能判断下一步该写 PRD、技术文档还是运营文档。
- 飞书发布、通知、任务指派统一走官方 `lark-cli` 当前登录态和权限，避免自建复杂 Adapter。
- 智能眼镜素材通常是文件资产，缺少稳定入库、转写和证据化流程。
- Agent 如果自优化失控，可能把敏感会议内容写入长期记忆或自动扩大权限。
- Hermes 生态近期存在供应链风险，不能把高权限执行链交给未隔离运行时。

## 5. 成功指标

- 10 分钟以内会议音频可生成可读纪要草稿。
- 60 分钟以内会议可生成纪要和至少一种后续文档草稿。
- 90% 以上行动项包含负责人、任务、时间或待确认原因。
- 所有关键结论都有 evidence id，或明确标注为推断/待确认。
- 飞书能力 100% 来自官方 `lark-cli` 直通，不复刻自定义 wrapper。
- Hermes sidecar 0 次直接访问飞书/Rokid token，0 次直接修改生产 skill。

## 6. 核心用户旅程

### Journey A：会后本地文件总结

1. 用户把录音/视频放入本地会议目录。
2. Agent 识别文件类型、建立 metadata 和 hash。
3. Agent 转写并建立 evidence index。
4. Agent 生成会议纪要。
5. Document Router 判断会议类型并生成后续文档。
6. QA 检查事实、隐私和缺口。
7. 用户确认是否发布到飞书。

### Journey B：Rokid 文件导入

1. 用户从 Rokid/手机端导出会议录音、视频或图片。
2. Rokid Bridge 扫描导出目录。
3. Agent 把素材作为 meeting artifact 导入。
4. 后续流程与本地文件总结一致。

### Journey C：飞书协同

1. Agent 读取用户授权范围内的飞书会议记录、文档或日历上下文。
2. Agent 通过 `feishu_cli` 直接调用官方 `lark-cli`。
3. Docs、Drive、Wiki、IM、任务、日历等操作由官方 CLI 子命令完成。
4. 用户明确要求发布前确认时，调用可选 confirmation checkpoint。

### Journey D：复盘与自优化

1. 任务结束后 PI 输出脱敏 trajectory。
2. Hermes sidecar 读取 trajectory。
3. Hermes 输出 memory、prompt、skill、eval proposal。
4. 人工 review 后小步合入。
5. 回归测试通过后进入下一轮使用。

## 7. 功能范围

### 7.1 输入与证据化

必须支持：

- 本地音频文件。
- 本地视频文件。
- 图片/截图。
- Rokid 导出目录中的会议素材。
- 手工补充的会议背景、参会人、目标和客户信息。

应支持：

- 飞书会议记录和会议纪要读取。
- 飞书文档、Wiki、IM 片段作为补充上下文。

输出：

- artifact metadata：`artifact_id`、`source`、`path`、`hash`、`privacy_level`、`created_at`、`imported_at`。
- evidence index：`evidence_id`、`artifact_id`、`time_range`、`speaker`、`text`、`confidence`、`tags`。

### 7.2 会议理解

必须提取：

- 会议主题。
- 背景和目标。
- 核心结论。
- 关键讨论。
- 决策和分歧。
- 行动项。
- 风险与开放问题。
- 下一次沟通清单。

所有关键结论必须标记来源：证据、推断或待确认。

### 7.3 文档路由

Document Router 根据会议内容选择输出类型：

- 产品需求会：纪要 + PRD + 客户需求确认表。
- 技术方案会：纪要 + 技术架构文档。
- 运营策略/复盘会：纪要 + 运营文档 + 复盘文档。
- 商务/客户沟通会：纪要 + 需求确认表 + 跟进邮件/飞书草稿。
- 混合会议：输出纪要，并拆分多份文档。

路由必须输出：

- 被选择的文档类型。
- 选择原因。
- 证据依据。
- 信息缺口。
- 不生成某类文档的原因。

### 7.4 文档生成

文档必须可直接进入飞书 Wiki 或项目知识库。

PRD 默认结构：

- 背景与问题。
- 目标用户。
- 目标与非目标。
- MVP 范围。
- 用户流程。
- 功能需求。
- 非功能需求。
- 数据/权限/安全。
- 验收标准。
- 待确认问题。

技术架构默认结构：

- 背景与目标。
- 系统边界。
- 模块分层。
- 数据流。
- 接口/Schema 草案。
- 权限与审计。
- 部署与运维。
- 风险与备选方案。
- 测试计划。

运营文档默认结构：

- 运营目标。
- 目标对象。
- 当前问题。
- 策略假设。
- 流程/SOP。
- 指标体系。
- 资源与节奏。
- 风险与复盘。

### 7.5 飞书集成

第一优先级：

- 官方 `lark-cli` 配置、登录和能力发现。
- `feishu_cli(args, stdin?, timeoutMs?, parseJson?)` 直通工具。
- Docs、Drive、Wiki、IM、Calendar、Tasks、Meetings、Sheets、Base 等官方 CLI 支持能力。

不做：

- 自定义 `read_doc/create_doc/send_im/move_doc` wrapper。
- Feishu action enum。
- approval-store。
- 默认 dry-run。
- 飞书专用审计日志或消息 hash。

### 7.6 Rokid 接入

第一阶段只做文件导入：

- 扫描用户指定的 Rokid 导出目录。
- 识别音频、视频、图片和 metadata 文件。
- 建立 artifact metadata。
- 进入本地会议处理 pipeline。

不做：

- 眼镜端实时采集。
- 绕过官方鉴权。
- 未授权上传原始音视频。
- 把原始会议内容写入长期记忆。

### 7.7 自优化

PI 负责执行，Hermes 负责事后学习建议。自优化只允许通过 proposal 机制进行：

- Memory proposal。
- Prompt patch proposal。
- Skill patch proposal。
- Eval proposal。

proposal 必须人工 review 后才能合入。

## 8. 非功能需求

- 本地优先：默认在本机处理和存储会议素材。
- 可追踪：工具调用、发布结果和 proposal 有运行摘要，不保存凭证或原始敏感内容。
- 可追溯：文档结论可回溯 evidence id。
- 飞书直通：飞书写动作依赖官方 CLI 登录态、scope 和返回结果。
- 最小权限：每个 integration 只拿当前任务所需权限。
- 供应链安全：禁用已知受影响依赖，生产运行依赖必须锁版本。
- 中文优先：默认输出中文，但保留英文技术名词。

## 9. Phase 执行

### Phase 0：文档与安全基线

完成本文档、架构、skill、权限、复盘和 agent team 分工。确认数据分级、依赖禁用、飞书权限和 Rokid 文件来源。

### Phase 1：本地 MVP

实现媒体导入、转写、纪要生成、文档路由、PRD/架构/运营文档草稿和 QA 检查。

### Phase 2：飞书协同

通过 `feishu_cli` 直通官方 `lark-cli`，完成飞书读、写、移动、IM、任务、日历等官方 CLI 支持能力。

### Phase 3：Rokid Bridge

实现本地导出目录扫描和 MCP Bridge 工具。实时采集后置。

### Phase 4：自优化

建立脱敏 trajectory、Hermes sidecar proposal、人工 review 和回归测试。

### Phase 5：生产增强

增加项目知识库、多会议串联、模板版本管理、飞书状态同步和可观测性。

## 10. 验收标准

- 能为本地媒体生成 metadata、转写和 evidence index。
- 能生成结构化会议纪要。
- 能根据会议内容选择后续文档类型并说明理由。
- 能生成 PRD、技术架构、运营文档和需求确认表草稿。
- `lark-cli` 未安装时返回清晰错误。
- 安装 CLI 后能通过官方子命令执行飞书读写动作。
- Rokid 第一阶段素材以文件导入进入 pipeline。
- Hermes sidecar 只能读取脱敏 trajectory 并输出 proposal。
- 依赖策略明确阻断 `mistralai==2.4.6`。

## 11. 暂不做

- 完整眼镜端 App。
- 实时音视频采集。
- 自动剪辑或复杂视频理解平台。
- 把飞书凭证、session 或 token 写入仓库。
- Hermes 直接操作飞书/Rokid。
- 自动把复盘结论合入生产 skill。
